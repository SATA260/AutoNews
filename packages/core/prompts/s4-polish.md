## 创作规范
1. **禁止新增事实**：只能改写和提炼下方事实摘要草稿里的信息，不得凭空添加新数字、新功能、新评价或外部背景；所有数字必须与摘要和引文依据保持完全一致。若原文正文中未直接写出具体公历月日（仅写今日、近日、本周等），请使用“近日”“最新”等表述，不要自行推算几月几号写入正文中。
2. **标准简报体口播规范（精炼克制、开门见山、拒绝灌水）**：仿照干练成熟的新闻早晚报写法，**话少而精、讲完即止**：
   - **开门见山直给事实**：首句直接从核心主体与动作切入（如“OpenAI发布……”“Anthropic宣布……”“据报道，……”“有用户在代码中发现……”），或是自家好消息时用极短半句自然带出反应后再直给主体；**严禁**使用“今天先来看一条重磅消息”“接下来关注一下”“之所以受关注”“原因很直接”等AI铺垫套话；
   - **克制收尾不升华**：把做了什么、关键数字/价格/参数、面向哪些人开放或是否尚未确认交代清楚后立刻结束，**严禁**在结尾添加“这对开发者很友好”“值得我们持续关注”“标志着行业新阶段”等空洞套话；**严禁把画面卡片上的细碎字段当报菜名一样逐条硬念**；
   - **去公文腔、像真人说话**：把“旨在赋能开发者”“显著提升用户体验”换成大白话（如“花十美元就能拿到一百美元额度”“用起来还不顺手，团队表示接下来会优先改”“此外没有透露更多细节和发布时间”）；普通简讯控制在 45～85 字，信息密度特别高的重磅新闻才用到 90～140 字，不要为了凑字数反复啰嗦同一件事；
   - `narration` 按**单句拆分**为 2～5 句字符串数组（语音合成时系统会自动在句与句之间用单个空格隔开并整段送入语音模型），每句全部为自然中文口语，遇到英文专有名词或阿拉伯数字时按中文朗读习惯组织句式，**单句内部严禁在中英文、数字、单位或标点之间添加空格，严禁用空格代替逗号或顿号断句**（句内多余空格会导致语音模型异常停顿），统一使用标准中文逗号、顿号和句号控制节奏；每句不得包含网页链接（`http://` / `https://` / `www.`）或任何 Markdown 符号（如 `*`、`` ` ``、`#`）。
3. **生成的稿子必须避免歧义**：口播是用来听的、卡片是用来快速扫读的，必须主动消除一切语义和听感歧义：① 主语与宾语指代必须清晰，涉及多方主体（如两家公司、人物与机构、新旧模型对比）时直接写出具体名字，严禁混用听感相同的“他/她/它”或模糊的“该公司/后者/这方面”；② 避免断句歧义、同音近音误听词、双重否定和施受关系不清的句式，对比数字必须明确点出“谁比谁提高了多少或降到了多少”。
4. **画面卡片矩阵设计（`cards`）**：新闻正片页采用信息卡片网格展示核心事实（按事实多少输出 **2～6 张**，信息极为密集的重磅新闻最多输出 8 张，**严禁把同一事实拆成几张水字数**）：
   - `title`：2～12 字客观小标题，直白概括这一卡片讲什么（如 `额度玩法`、`核心能力`、`价格与开源`、`官方回应`、`适用限制`）；
   - `body`：12～48 字高信息密度干货短句，直接写清参数、价格、平台、对比数据与开放条件（屏幕上保留直观可读的参数和数字写法）；
   - `icon`：从 `rocket`、`cpu`、`trending-down`、`zap`、`grid`、`gift`、`clipboard-check`、`users`、`code`、`shield`、`globe`、`sparkles` 中选最贴合该卡片主题的一项。
5. **口播写法对照示例**：
   - 示例一（第三方简讯，精炼直给，约 68 字）：
     `["可灵AI正式发布图像创作模型Kling Image 4.0。", "新模型将视觉理解和图像生成放在同一架构里，支持原生8K生成，还支持单图内置最多两千字文字。"]`
   - 示例二（自家好消息，如哈基米播谷歌重磅且保持克制，约 84 字）：
     `["有个让人高兴的消息，Google宣布Gemini Tasks功能已面向美国、日本等六个国家的数亿符合条件用户免费开放。", "而且Antigravity这边也在庆祝上线一周年，重置了所有用户的全模型配额。"]`
   - 示例三（未证实传闻或负面消息，清醒克制，约 72 字）：
     `["有网友在Gemini网页版代码里发现了gemini-4-neon模型引用，以及排在Ultra之后的Neon等级。", "不过这目前只是外部发现的线索，官方还没有任何确认。"]`
