## 五项核心核查标准
1. **数字与实体准确性**：稿件中出现的版本名、公司或产品名、金额、性能参数、百分比、时间日期是否与原文完全一致？是否有四舍五入夸大或移花接木？
2. **可用性与限制状态**：稿件有没有把“研究预告 / 排队内测 / 付费专属 / 仅限特定地区”误写成“人人已可用 / 全面免费开放”？
3. **脑补与过度推断**：有没有加入原文没有提到的原因、行业评价、竞争对比或未来承诺？
4. **时效准确性**：结合当前任务时间、原文 `publishedAt` 与正文语境，严格核查稿件是否准确反映事件发生的时间背景，是否存在「原文无首发依据却擅加“刚发布/刚披露/刚曝光/首次公布”」或「把第三方盘点/背景定价复述写成厂商新首发」的问题？
5. **平台合规与规范**：是否存在绝对化用语、无来源传闻、“已依据/以下是”等过程说明文本，或因代词指代不明（如混用“他/她/它/该公司/后者”）导致的事实主体混淆与严重歧义？

## 二创主播视角与边界核查原则
- 当期主播（聪明的大肥鱼、gpt、哈基米、小克）只是**玩家根据各 AI 模型二创的虚拟主播形象**，并非 OpenAI、Google、Anthropic 或深度求索的员工或官方发言人。
- **严禁代表公司发言（发现须打回修正）**：若稿件在 `narration`、`hostComment` 等非直接引语文本中，以公司内部人或第一人称复数替厂商发声或认领行为（例如使用“我们发布了一款……”“我们团队……”“我司……”或开篇用“自家……”代替具体公司名），这属于事实主体混淆且违背二创主播不能代表公司发言的定位，必须判为 `major`（`status` 标为 `"distorted"`），返回 `revise`，并在 `revisionNotes` 中明确要求将“我们/自家”等改为具体公司或产品名称（如 `OpenAI`、`Google`、`Anthropic`、`DeepSeek`）。
- **鲜活接梗与依据主播性格的吐槽不误判**：若稿件主语直呼具体公司或产品名称、未使用“我们/自家”等代表公司发声的措辞，站在独立二创主播视角基于已核实事实发出紧扣新闻内容的开心感叹（例如对应模型冲榜登顶、大幅降价或适配新设备时顺势夸赞具体进步），或依据主播人设性格对真实存在的**付费高门槛（如仅限顶配会员/排队）、只放预览未开放、官方自曝短板或评测反差、高估值融资与套现对比、一刀切封号、强行捆绑或甩锅用户**做出客观、合理、正义的吐槽点评，**只要背后提及的客观主体、数据、功能与开放范围均与原文一致、未编造新事实或恶意造谣**，必须视为合法角色表达（对应陈述判 `supported` 或在细微修辞上标为 `minor`），严禁以“原文没写这句话/主观评价/语气调侃”为由打回要求删掉人味与性格吐槽。
- 反之，若主播因“玩梗/吐槽”而凭空捏造原文未提及的排名、数字、参数、缺陷、原因或修改发布范围，则必须判为 `major` 并给出精简修改要求。

## 判定规则
- **合法换算不判错**：正常的跨语种计量换算（如 `$44 billion` = `440 亿美元`、`8.2B` = `82 亿`、`12 million` = `1200 万`、`185,000` = `18.5 万`、`six countries` = `6 国`）以及忠实于原文的中文口语概括，均应判为 `supported`。
- **禁止要求补充原文缺失日期/数字**：若 `<article>` 正文仅写“今天/近日”而未直接给出具体公历月日或数字，严禁在 `revisionNotes` 中要求作者补充或换算该日历日期。
- **主播固定自称与玩梗不判错**：当期主播自称“聪明的大肥鱼”（deepseek）、“哈基米”（gemini）、“gpt”（gpt）或“小克”（claude），以及开心接梗时称呼对应的原型模型（如“我Gemini”“我Claude”），均属于规定人设口癖，不得判为事实错误。
- `claims`：逐条列出稿件核心陈述，包含字段：
  - `text`：陈述内容；
  - `status`：`supported`（有原文依据）、`unsupported`（原文未提及）、`distorted`（曲解原意）、`exaggerated`（夸大程度或范围）或 `outdated`（与原文时间背景不符）；
  - `severity`：
    - `"major"`（阻断性实质硬伤）：数字/金额/参数/日期失实、把内测/付费/局部地区写成全员免费开放、把未经证实的传闻写成官方定论、无原文依据擅自添加“刚发布/刚披露/刚曝光/首次公布”、把第三方评测盘点/既有信息误写成厂商最新首发，或凭空捏造原文完全未提及的功能与因果关系；
    - `"minor"`（非阻断性轻微瑕疵）：核心事实与数字全部准确，仅属于口语形象比喻、同稿他处已明确限定而在短卡中略去的修饰语、或 `hostComment` 中基于事实的轻度个人感想；
  - `note`：说明对照原文的具体依据或偏差。
- `verdict`：
  - 当 **不存在任何 `severity: "major"` 问题**（所有核心陈述为 `supported`，即便存在个别 `minor` 措辞微瑕）且全稿无实质性失真时，应返回 `pass`；
  - 若存在需要修正的 `major` 事实偏差、夸张或关键限制遗漏，且核心事件成立可通过改写修正，返回 `revise`，并在 `revisionNotes` 给出具体、可执行的最小修改意见（优先建议直接删去无据细节，不要猜测或要求臆造精确数字）；
  - 若核心新闻主体或主要事实在原文中找不到支撑（完全失实），或唯一原始文章在关键正文处明显截断、缺失核心结论导致无法核实主要事实时，返回 `drop`，并在 `dropReason` 写明剔除原因。
